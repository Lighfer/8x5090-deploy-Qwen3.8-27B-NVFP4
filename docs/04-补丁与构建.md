# 固定输入、补丁与构建

本仓库保存源码重建路径，不分发镜像层、权重、SDK或编译产物。构建所需公共引用见`locks/`，软件版本和源码身份见`STACK.json`。在公开来源仍可取得这些固定输入的前提下，可以重新构建相同软件与修正逻辑；Docker层创建时间、编译器路径等可能使新镜像ID不同。身份检查应比较固定输入、实际版本、修正后文件和功能，不能把某人的本地镜像ID当下载地址。

## 必要修正

| 位置 | 原因与处理 | 边界 |
| --- | --- | --- |
| `sources/worker-memory/` | LXC内Worker可能把物理宿主总内存当成可调度内存。读取LXCFS的meminfo和只读LXC根cgroup，区分LXC整体与Worker自身用量 | 容量实时读取，不写固定总量。裸机配方不挂载该模块 |
| `sources/worker-runtime/` | 默认pause进程空间使同机P/D互相隔离，CUDA IPC传输可能退回较慢路径。仅在明确启用且存在KV传输参数时，共用Worker PID空间 | 不影响普通模型；活动P/D存在时不能单独重建Worker |
| `sources/vllm/nightly-patches/` | 非法帧、MsgPack或字段可能使NIXL握手线程退出，而HTTP健康仍返回成功。严格验证消息，丢弃非法输入后继续监听 | 固定nightly原文件SHA；不能向二进制握手端口发送HTTP探测 |
| `sources/vllm/flashinfer6204/` | 官方FlashInfer #6204移除NVFP4写缓存时对CUDA比例因子的重复CPU回读同步 | 只重放官方Python差异，核对原内核保护；不改CUDA内核、不编译CUDA |
| `sources/vllm/optimizations/` | 固定9项官方上游差异，降低MRV2的CPU暂存开销、改进SM12x GDN非CP预填充，并修复多模态及显存预算问题 | 完整身份、逐步散列和两处上下文适配均登记；构建只做CPU验证，GPU JIT在真正启动时执行 |
| `sources/vllm/lmcache-cuda/` | 固定nightly的Torch为2.14，而LMCache 0.5.6公开轮子的构建固定Torch 2.13；CUDA扩展导入缺失符号后回退实现不支持blocks-first的非连续块步长 | 使用固定0.5.6源码和当前镜像工具链成对重建`lmcache.cuda_ops`和共享C++类型模块`lmcache.lmcache_native`，不升级Python包、Torch、CUDA或驱动 |
| `sources/router/` | Router 0.1.16原生扩展的P/D类型、多路由阶段策略、动态成员前缀记录和cache_salt路由域需要修正 | 保留原生协议；固定源码与Cargo.lock，不能直接套其他Router版本 |

官方修复来源：[FlashInfer #6204](https://github.com/flashinfer-ai/flashinfer/pull/6204)，固定提交`3821440929ee342fe9f939dbf5186c3e667a851c`。Python修改前后及已有内核的SHA256均在`inputs.json`，应用器遇到未知源码拒绝执行。发布日期晚于修复合并，不等于所依赖wheel已包含修复；升级时必须读实际文件。

NIXL有两套明确分开的补丁：`nightly-patches/`用于当前固定nightly；`patches/`仅用于legacy运行镜像，不能互换。`Dockerfile.legacy`用于恢复需要旧缓存运行依赖的独立缓存服务，不是当前P/D的默认框架。

## 实际编译了什么

主要人工编译的是Router的Rust原生扩展。构建器从PyPI取得0.1.16源码，先核对完整源码包SHA，再应用两个脚本，并验证`patched-source.sha256`里的Rust文件及Cargo.lock。使用固定Rust SDK、`cargo build --locked --release --lib --features pyo3/abi3-py38`构建。临时容器内安装编译依赖，ZeroMQ沿用锁定依赖的静态构建方式，避免给运行镜像新增系统动态库。

当前运行镜像另外重建LMCache CUDA扩展。官方[0.5.6源码发布](https://pypi.org/project/lmcache/0.5.6/)的`pyproject.toml`固定Torch 2.13，而本镜像固定2.14。原`.so`虽然存在，直接导入却会因`c10_cuda_check_implementation`缺失符号失败；`CudaDeviceOps.ensure_native()`捕获ImportError并打印“compiled extension not found”，随后Torch回退在`_normalize_paged_layers()`明确拒绝非连续块步长。结果是缓存池健康、模型生成正常，却一直无法写入共享缓存。不能只看文件存在、进程健康或开关启用就判定可用，也不能删除报错检查来伪装缓存命中。

构建脚本核对源码包大小及SHA256，调用上游`CudaProfile`，成对编译同版本CUDA与公共C++扩展，沿用当前Torch 2.14/CUDA 13与C++ ABI，目标SM120。NVIDIA头文件使用镜像已有`nvidia/cu13/include`，不安装另一套SDK；该路径是容器内Python包约定。`MAX_JOBS=1`、`NVCC_THREADS=1`控制单次编译的内存，当前配方要求构建限额至少8GiB且仍保留运行余量。原包版本不伪改，构建来源与新扩展SHA登记到镜像内`/opt/gpustack-v032/lmcache-cuda/abi.json`；该目录只用于派生镜像构建及核验。

构建阶段必须直接导入扩展并确认未初始化CUDA。`verify-gpu.py`另验证带块间隔的字节和BF16数据经过GPU→CPU→不同GPU块后逐位一致，不加载模型，张量峰值限制64MiB；调用者须事先授权并只向核验容器暴露一张GPU，不能把容器逻辑`cuda:0`当成主机固定卡号。该核验也不能代替上线前的跨P读回验证。

运行镜像以固定官方镜像为底，修改NIXL、vLLM与FlashInfer的Python/CuTe DSL源文件，并执行无GPU核验。它没有把第三方5090分支的大量CUDA修改叠加到nightly。首次模型启动时FlashInfer和Torch按实际硬件、形状生成JIT缓存，这是可再生内容，不随仓库传播；换CUDA、Torch、架构或框架版本后重新生成。候选优化的完整来源与适用条件见[候选优化与下次启动](08-候选优化与下次启动.md)。

## 构建命令与限制

```bash
# 变量由本次维护提供；构建目录必须在仓库之外且尚不存在。
python3 -B tools/build-stack.py --work "$BUILD_DIR" --prefix "$IMAGE_PREFIX" \
  --release "$RELEASE" --cpus "$BUILD_CPUS" --memory-gib "$BUILD_MEMORY_GIB"
python3 -B tools/build-stack.py --work "$BUILD_DIR" --prefix "$IMAGE_PREFIX" \
  --release "$RELEASE" --cpus "$BUILD_CPUS" --memory-gib "$BUILD_MEMORY_GIB" --execute
```

默认只预览；执行后生成本次新runtime/router标签，既有标签拒绝覆盖。基础镜像按公共摘要和Linux/amd64核对，再创建本次构建别名供离线派生层使用，避免构建器隐式解析可变标签。Rust构建允许取得Cargo/APT依赖，签名和TLS检查保持开启。构建器限制CPU及内存，并在执行前检查运行余量；不能因为“不使用GPU”就忽略与生产争抢内存。

LMCache源码默认从锁定的官方地址下载到仓库外构建目录；也可先取得并校验源码包，再给`build-stack.py`增加`--lmcache-archive "$LMCACHE_SOURCE_ARCHIVE"`。网络受限时沿用`--proxy`指定的本次回环代理，不关闭TLS或临时修改宿主DNS。

只构建兼容旧缓存镜像时使用独立的外部目录和标签：

```bash
python3 -B tools/build-stack.py --variant legacy --runtime-only \
  --work "$LEGACY_BUILD_DIR" --prefix "$IMAGE_PREFIX" --release "$LEGACY_RELEASE" \
  --cpus "$BUILD_CPUS" --memory-gib "$BUILD_MEMORY_GIB" --execute
```

将新标签登记到外部环境文件相应字段，生成器会读取目标机真正的镜像ID进行私有锁定。模型、Router及缓存运行镜像应分别登记，不能只改某个网页image字段后假定启停工具和回滚也已同步。

## 依赖保管与复现的范围

模型按完整revision和18项文件SHA固定；平台镜像、基础镜像与Rust SDK按公开摘要固定。Cargo依赖由原Cargo.lock约束。APT和部分Python工具仍从发行源取得，无法承诺未来字节完全相同的编译环境；重建后必须执行源码/ABI和真实推理验收。可由使用者在自己的仓库外镜像库保存已验收镜像，并记录摘要；本公共仓库不接收该环境的镜像ID和备份包。

补丁源码重放可运行`tools/verify-source.py`，完整性核对运行`tools/verify-integrity.py`。这两项不启动GPU模型，不替代目标硬件上的部署验收。
