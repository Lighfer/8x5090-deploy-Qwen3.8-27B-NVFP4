# 方案、启停与缓存

在用户自己的私有部署目录执行生成的`switch-pd.sh`，不在源码模板目录操作模型。

```bash
./switch-pd.sh status
./switch-pd.sh stop
./switch-pd.sh start
./switch-pd.sh 1p1d-cache
./switch-pd.sh 1p1d-no-cache
./switch-pd.sh 2p2d-cache
./switch-pd.sh 1p2d-6gpu-cache
```

## 配方参数

| 方案 | P每实例 | D每实例 |
| --- | --- | --- |
| 1P1D开启CPU缓存 | TP4、seq12、batch16896、显存比例0.84、长请求6144自适应 | TP4、seq24、batch1536、显存比例0.84 |
| 1P1D关闭CPU缓存 | 同一参考P参数 | 同一参考D参数 |
| 2P2D | 两个TP2，各seq6、batch9216、显存比例0.84 | 两个TP2，各seq12、batch1536、显存比例0.84 |
| 六卡1P2D | TP2、seq6、batch9216、显存比例0.84 | 两个TP2，各seq12、batch1536、显存比例0.84 |

共同参数：最大上下文204800、block/mamba-block1536、MTP3、NVFP4 KV、BF16 Mamba状态、align、前缀缓存、分块预填充、默认xhigh。JSON聊天参数只保留一份，推理/工具解析器分别为qwen3和qwen3_coder。完整配置以`recipes/`为准。

模型级`restart_on_error`明确关闭，避免共享PID/IPC的单角色故障被平台反复局部拉起。发生失败先保留日志并使用整组恢复流程；这与控制服务、Worker容器的`unless-stopped`重启策略不同。缓存服务自身保留独立的重启设置。

最多64张图片，统计整次请求全部历史图片；预处理总像素预算为65536～1048576，视觉权重按TP分片，CPU预处理缓存关闭，保留启动内存分析。保留图片词元分块，不开启`--disable-chunked-mm-input`。某些模型的完整启动预算高于单张缩放后词元数，不能只用处理器元数据推导D的小批预算一定兼容。

图片数量限制、预处理缩放和显存比例不是任意输入下绝不OOM的保证。超大原图解码、并发以及客户端覆盖处理参数仍需要目标业务验收。

## 切换的实际行为

切换依次执行只读预检、隔离入口、等待在途请求、停止模型整组、释放旧专用CPU池、创建目标池、应用完整配置、等待全部角色、核对实际进程和接口，再恢复访问。失败按原模型和缓存快照回滚；回滚失败保持503。

`stop`释放本模型GPU及专用CPU池，保留控制服务、Worker和其他业务；`start`从私有状态文件读取上次方案名，再加载当前正式模板和镜像身份。它不恢复已经释放的缓存热数据。健康的相同方案通常不重启，`--restart`可明确要求整组重建。

```bash
./switch-pd.sh 1p1d-cache --dry-run
./switch-pd.sh 1p1d-cache --health-only --drain-timeout 600
./switch-pd.sh recover
```

`--dry-run`不隔离入口或修改模型。默认切换会执行短生成检查；`--health-only`只跳过生成，不能跳过成员、参数、内存或入口核验。`--extended-check`增加上下文、并发和缓存检查，不能与`--health-only`同时用。

后台由systemd执行，关闭SSH不终止切换；`status`查看进度。默认排空等待有上限，超时后剩余请求可能被中断，维护前应根据业务选择等待时间。长模型启动应看进程、日志和任务阶段，不能只靠一次超时判断停止。

## 共享缓存的边界

CPU池容量由环境输入决定，1536分块、LRU、触发水位0.85、回收比例0.10、独立对象组、不启用P2P或L2。只接P，D通过NIXL接收P的KV。它帮助复用移出GPU的前缀，不扩大D活动请求需要的显存。

`1p1d-no-cache`表示不绑定CPU池；正常切换会删除本模型独占的旧池。若仅为还原“未绑定但保留缓存服务”的维护状态，可以在模型启动完成后，明确使用私有API工具创建生成的缓存定义，而不绑定模型：

```bash
python3 -B gpustack-local-api.py POST /v2/cache-services --body cache-service.json --output cache-created.json
```

这会实际分配用户指定容量，并可能建立GPU上下文；不是关闭缓存后的常规推荐，也不代表模型在使用该池。下一次正式切换仍会按所属关系清理它。需要兼容旧缓存运行环境时，通过独立legacy运行镜像构建，并在本次环境文件中明确填写`images.cache`。

## 手工配置与卡号

手工修改网页后，当前状态可能不再匹配正式方案。`stop`拒绝猜测该记住哪套方案；选择正式方案重新应用之前应先核对差异。仅对已登记、实际ID匹配的旧推理镜像允许版本过渡识别，其余参数不放宽。

六卡方案按本次`six_card_order`映射，缓存池也限制同一集合。返回八卡前检查新增GPU是否被其他业务使用；不会杀进程或默认抢占某两个固定序号。
