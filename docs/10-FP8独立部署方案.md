# FP8独立部署方案

## 范围与输入

`1p1d-cache-fp8`使用官方`Qwen/Qwen3.8-27B-FP8`权重、P/D各TP4、静态`fp8_e4m3`GPU KV、BF16 Mamba状态与P专用CPU共享缓存。原四种模式的NVFP4权重、NVFP4 KV、并发和GPU预算保持原值。对外模型别名和端口来自用户环境输入，不随权重目录变化。

在仓库外环境文件中保留原`paths.model_directory`，另外明确填写`paths.fp8_model_directory`。两个目录必须独立，并处于同一个`paths.model_parent`挂载内。缺少新字段或明确填null时，仅生成原四种方案；不会猜测FP8目录，也不会用FP8覆盖旧权重。

固定来源见`locks/model-downloads-fp8.json`：完整revision为`017b9c7af6b5689d5dd426a76e0bc077eb5ca20a`，66个权重分片合计30866866928字节；同时保留启动配置、分词器和聊天模板的SHA256。模型文件下载至用户指定的仓库外目录，不进入源码包。

```bash
# 变量均由本次目标环境提供；默认只预览，不下载。
python3 -B tools/fetch-model.py --precision fp8 --target "$FP8_MODEL_DIR"
# 仅在需要取得外部权重时执行；已有文件会先完整验证，拒绝覆盖不同内容。
python3 -B tools/fetch-model.py --precision fp8 --target "$FP8_MODEL_DIR" --execute
# 已有权重的完整内容验证，不访问网络。
python3 -B tools/fetch-model.py --precision fp8 --target "$FP8_MODEL_DIR" --verify-only
python3 -B tools/configure.py --site "$SITE_FILE"
```

## 参考参数与理由

| 项目 | FP8独立方案 |
| --- | --- |
| P / D实例 | 各1个，各TP4，GPU集合来自本次输入 |
| 权重量化 | 显式`--quantization=fp8`；128×128分组，动态激活量化由权重配置决定 |
| GPU KV | 两端同为`fp8_e4m3`，采用一致静态尺度 |
| Mamba | `align`，SSM状态`bfloat16` |
| Attention / GDN | `FLASHINFER` / `flashinfer`；Mamba计算保留`triton` |
| GPU内存比例 | 0.84，为算子临时空间保留余量，不盲目增加KV显存预算 |
| P并发 / 每轮token预算 | 8 / 8192 |
| D并发 / 每轮token预算 | 16 / 1536 |
| P长请求分段 | 1536，自适应；单请求可利用剩余总预算 |
| 上下文上限 | P/D共同262144，模型原生范围；启动时必须通过实际GPU容量检查 |
| 块大小 / CPU池chunk | FP8使用1024；P/D及新建CPU池一致，原NVFP4模式仍为1536 |
| 草稿 | 原生MTP3；保留固定版本所需参数，不外加其他模型的草稿 |
| 默认思考 | xhigh，保留历史思考；只有一份聊天模板参数 |
| 图片 | 每请求最多64张，单张约百万像素；CPU预处理、处理缓存为0、保留视觉启动画像 |
| 日志统计 | 3秒 |
| CPU共享缓存 | 容量与最低空闲主存由环境输入；只绑定P，不扩大D活动请求的显存 |

FP8权重较当前混合NVFP4权重更大，FP8 KV页也更大。相较NVFP4的TP4参考配方P12/D24，降低并发和P批预算用于减少激活、图捕获和MTP峰值；不是未经实测的性能最优结论。并发上限并不保证所有请求都能同时填满最大上下文，GPU KV不足仍可能进入调度等待或抢占。

新模式单独设置vLLM、FlashInfer、CuTe和CUDA编译缓存命名空间，避免与原精度的编译产物混淆。源码配方不固定主机缓存目录；使用的是Worker数据卷内部的上游运行目录约定。

## FP8 KV的缩放约束

官方检查点没有随权重提供K/V校准尺度。此配方采用`fp8_e4m3`的默认静态尺度1.0，使P与D独立加载时得到一致解码规则。**不得添加两端各自计算的`--calculate-kv-scales`来替代离线校准**：当前NIXL传输不负责同步各实例的标量尺度，KV页即使传输成功也可能被错误解释。

静态尺度一致只解决传输规则一致性，不表示已经完成业务精度校准，不能保证换成FP8后所有任务必然变好。**本发布没有完成可靠离线校准，明确回退到vLLM官方默认1.0；不能称其为“官方精度优先推荐1.0”**。官方精度优先推荐使用数据集校准。不得为了消除警告借用其他检查点的尺度或填入任意值。

可靠校准必须有独立GPU/内存资源，覆盖固定官方FP8权重、归一化/位置编码后的KV写入、主模型16层完整注意力和1层MTP注意力；不能在承载业务的进程中加采样钩子。本次发布的源码依据、回退标准、图片预算、布局比较和未来校准验收步骤见[FP8校准与布局核验](11-FP8校准与布局核验.md)。

依据：[vLLM量化KV说明](https://docs.vllm.ai/en/latest/features/quantization/quantized_kvcache/)、[NIXL量化兼容性](https://github.com/vllm-project/vllm/blob/main/docs/features/nixl_connector_compatibility.md)、[Qwen官方模型](https://huggingface.co/Qwen/Qwen3.8-27B-FP8)。升级时以实际固定源码的行为重新核对，不把当前网页当成未来版本保证。

## 切换、回退与下次启动

在私有安装目录执行：

```bash
./switch-pd.sh 1p1d-cache-fp8 --require-drained --drain-timeout 600
./switch-pd.sh 2p2d-cache --require-drained --drain-timeout 600
./switch-pd.sh 1p1d-cache --require-drained --drain-timeout 600
./switch-pd.sh stop --require-drained --drain-timeout 600
./switch-pd.sh start --require-drained --drain-timeout 600
```

模型目录纳入模式签名、目标写入、幂等判断和启动参数核验。不能只比较相同的对外模型名称。切换继续先预检、暂停新请求、严格排空、停止全部角色、销毁旧CPU缓存池，再加载目标模型并重建同容量的新池。NVFP4缓存不能转作FP8使用，切回时也须重新建立池。

`switch-config.json`的`mode_chunk_sizes`分别记录各模式分块；默认`cache-service.json`保留NVFP4的1536。执行器只在冻结的目标事务副本中将FP8池改为1024，再给P绑定同一个值。失败直接恢复原池定义与原P关联，不能把新分块混入旧模式。

FP8启动后还会通过普通`/v1/models`和`/metrics`核对实际262144上限、1024管理块、1024 GDN块、缓存类型与已分配GPU块，并核对CPU池分块。缺失证据或框架自动上调导致不一致时验证失败，走原回滚。未启用`/server_info`等开发接口，也不通过删除检查来恢复入口。

Router校验同时核对固定镜像、启动参数及实时`get_server_info`和`workers`。启动日志已轮转时，不把缺日志当作策略失效；报告保留实际日志策略为null并注明证据来源。明确冲突的策略日志、缺失成员或非原生PD模式仍失败，不能静默放宽。

如果`next-start-release.json`处于`prepared`且明确含`target_mode`，下一次`start`采用该目标；显式模式参数优先，`stop`记录当前实际模式。成功后`model-state.json`记住最后成功模式，后续`start`按记忆恢复。仅准备配置不会重启服务或修改当前成功模式。开机应用仍尊重人工停机，不在同一开机周期自行激活。

启动失败恢复原模型目录、KV精度、参数、CPU池与启停状态；原方案验证通过才恢复入口。首次预备发布失败还会恢复其登记的旧文件。回滚失败保持入口关闭，不绕过检查放行业务。

## 验证范围

配置预检校验小型启动文件的完整SHA256、权重索引、分片存在和固定大小、MTP权重存在、TP4分组宽度及P/D布局。为避免每次切换读取几十GiB数据，预检不重新计算所有权重的完整散列；完整校验使用上方`--verify-only`。

合成环境中的模式互转、启停、路径恢复、故障回滚、缺分片拒绝和公开审查不能替代GPU验收。该模式在目标机器首次应用时，必须核验实际模型路径、全部角色健康、MTP接受、PD传输、CPU缓存写入与冷读回、显存/主存和图片工具接口。未执行这些项目时，应明确记录“只完成准备”，不得写成已经稳定上线或已测得提速。
