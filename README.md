# GPUStack 模型服务部署与维护

面向单机NVIDIA SM120推理环境的可复现部署配方，整理了GPUStack管理、vLLM预填充/解码分离、MTP、NVFP4 KV缓存、可选CPU共享缓存、固定OpenAI兼容入口，以及实际排障中形成的源码修正和操作边界。

**本仓库不保存任何人的服务器环境。使用前必须先提供本次环境信息，再生成仓库外的私有部署目录。** 模型权重、镜像、SDK、凭据、运行日志和数据库均不随源码分发。

## 固定软件与能力

| 组件 | 固定输入与用途 |
| --- | --- |
| GPUStack / Runtime | 2.3.0 / 0.2.6；管理控制服务、Worker及模型工作负载 |
| vLLM | 固定提交`e4a5b5537344b103ed10de7764378ef09604ef3d`，包版本`0.32.1rc1.dev466+ge4a5b5537` |
| FlashInfer | 0.7.2.post1，重放官方#6204的NVFP4同步修复及#6371的SM12x GDN优化 |
| Router | 0.1.16，保留P/D类型、阶段策略、动态成员与隔离域修正 |
| 推理配方 | Qwen3.8-27B-NVFP4；NVFP4 GPU KV、BF16 Mamba状态、MTP 3、默认xhigh |
| 可选共享缓存 | LMCache 0.5.6；只接P，容量由用户输入，开启提前查询 |

精确公共镜像摘要、模型文件版本和散列见`locks/`，必要源码补丁见`sources/`。不是任意未来nightly，也没有把旧分支的全部CUDA改动叠加到当前框架。

当前候选`e4a5b5537-opt-20261028`包含9项明确登记的上游回移，配合TP2通信、NUMA及独立编译缓存配置；源码依据、未启用方案和下次启动边界见[候选优化与下次启动](docs/08-候选优化与下次启动.md)。它已包含CPU验证工具；GPU性能应在目标机器启用后测量，不能从补丁数量推算提速。

## 使用顺序

1. 阅读[AGENTS.md](AGENTS.md)和[环境与边界](docs/01-环境与边界.md)，准备本次环境信息。将`config/site.example.json`复制到用户指定的**仓库外**位置，填写实际值。
2. 按[从零部署](docs/02-从零部署.md)取得固定公共镜像、构建运行镜像和Router、取得并校验模型，然后生成私有安装目录。
3. 网页创建集群和Worker注册令牌，将令牌填写到私有目录的`.env`；实际编号通过只读工具查询，再登记到本次环境文件并重新生成身份相关配置。
4. 按[方案与启停](docs/03-方案与启停.md)选择正式方案，完成目标机器验收后接入业务。

命令中的Shell变量都由本次用户环境提供，不能照抄别人的IP、目录、端口或卡号。

```bash
# 当前目录为源码仓库。以下路径变量均须事先由用户提供。
python3 -B tools/fetch-platform-images.py --execute
python3 -B tools/build-stack.py --work "$BUILD_DIR" --prefix "$IMAGE_PREFIX" \
  --release "$RELEASE" --cpus "$BUILD_CPUS" --memory-gib "$BUILD_MEMORY_GIB" --execute
python3 -B tools/fetch-model.py --target "$MODEL_DIR" --execute
python3 -B tools/configure.py --site "$SITE_FILE"
python3 -B tools/configure.py --site "$SITE_FILE" --execute
```

构建工具只生成新镜像，不修改运行服务。生成工具默认只预览；显式执行后写到用户提供的外部目录，并拒绝覆盖手工修改的受管文件。

## 四种方案

| 方案名称 | P | D | 共享缓存 |
| --- | --- | --- | --- |
| `1p1d-cache` | 1×TP4 | 1×TP4 | P专用CPU池 |
| `1p1d-no-cache` | 1×TP4 | 1×TP4 | 不绑定CPU池 |
| `2p2d-cache` | 2×TP2 | 2×TP2 | P共享CPU池 |
| `1p2d-6gpu-cache` | 1×TP2 | 2×TP2 | P专用CPU池 |

GPU实际序号、端口和缓存容量均来自本次输入。单实例并发与批预算、上下文、图片预算和运行参数在`recipes/`中；参考参数不等于任意硬件、任意业务的最优配置。开启与关闭CPU缓存的参考1P1D配方使用相同保守显存预算和长请求调度，便于比较。

## 目录

| 目录 | 内容 |
| --- | --- |
| `config/` | 只有字段和空值的环境输入示例 |
| `recipes/` | 四种通用拓扑、模型参数和缓存定义 |
| `templates/` | 由生成器渲染的Compose、入口、指标、启停及验证工具 |
| `sources/` | 必要源码输入、严格重放补丁、构建配方及校验工具 |
| `locks/` | 公开软件与模型的固定来源及散列 |
| `tools/` | 资源取得、构建、生成、公开检查、完整性核验和打包 |
| `tests/` | 合成环境下的安装、切换、回滚及安全边界测试 |
| `docs/` | 从零部署、性能理解、源码经验和维护方法 |

性能与缓存的取舍见[性能与缓存](docs/05-性能与缓存.md)，补丁原因见[补丁与构建](docs/04-补丁与构建.md)，故障恢复见[升级恢复与排障](docs/06-升级恢复与排障.md)。公开审查方法见[公开规范](docs/07-公开审查与AI使用.md)。
