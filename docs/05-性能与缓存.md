# 性能、命中率与等待

配方是经过问题排查形成的参考起点，不是任意硬件和业务的最优参数。公开仓库不保留任何服务器的请求记录、压力窗口、硬件测量或运行快照，不能把这里的配置当成本次重新压测结果。

## 先理解两个阶段

P负责读输入并建立状态，D负责继续生成。单个请求要先经过P再进入D；输入很短、已经命中或生成很长时，P可能很快空闲。GPU利用率不必始终两侧相同。判断协同是否正常应确认请求确实经过两个阶段、NIXL实际传输、D持续输出，并结合每侧服务时间和队列；不能只看一次显卡截图。

同机1P1D每侧TP4减少多P的重复前缀副本，也增加单P的处理能力。2P2D每侧TP2增加独立引擎数量，同时分散前缀和容量；六卡1P2D保留两个D，但P只剩TP2。应按未命中输入需求和输出需求选择，不能仅按角色数量推断吞吐翻倍。

`max-num-seqs`是可驻留序列数量，不代表每轮同时计算同样多条长输入。P12/D24是参考上限；实际还受批量词元预算、单长请求预算、KV/状态就绪和外部查询影响。提高seq而不提高有效计算能力，可能只增加驻留和长尾。

## 为什么限制长请求每轮计算量

参考1P1D保留P总批量16896，2P2D保留每个TP2 P的总批量9216；两者长请求分段阈值均为3072并启用自适应分配。3072是两个1536对齐单位，目标是在突发长输入下让更多请求获得推进机会，不能据此保证总吞吐提升。自适应开启时，实际分段可能大于3072；只有单条可调度请求时可以使用全部预算。继续降低到1536会增加分段轮数，必须有队列、单轮成本及业务首token数据支持，不能只为提高Running数量而调整。六卡方案保留其已有调度设置。

缓存提供方启用提前查询，让CPU缓存存在性检查尽早开始；不是把CPU传输成本变为零，也不能绕过未知KV布局。修改提供方后需要按整组维护流程重新建立对应运行实例。

## GPU使用率低不一定在丢缓存

vLLM日志的GPU KV usage主要反映正在被活动请求占用、不可立即回收的块，不是所有仍留在显存且可复用前缀的总占比。请求结束后，引用计数下降，usage可能回到0，但空闲块里仍可能留有可命中的前缀；下一请求可在覆盖之前复用。不能靠“禁止淘汰”让该指标变成真实已分配显存。

`nvidia-smi`显示进程显存，包括权重、KV、Mamba状态、工作区和图；空出部分显存用于峰值和临时分配。NVFP4只压缩相应KV，混合模型的Mamba状态仍为BF16，比例因子、对齐和元数据也占空间。扩大显存比例可能导致视觉、MTP或调优峰值OOM；不能把所有剩余显存都填成KV。

## 为什么同一会话仍可能不到95%

命中依据是实际词元前缀，而不是会话ID。以下情况都会降低显示值：新增问题和新增思考必然是新词元；工具结果、系统消息、模板或图片预处理变化可能破坏后续共同前缀；客户端整理历史、插入时间或重新序列化也会改变输入。`cache_salt`隔离域、路由到其他P、进程重启和容量回收同样影响复用。

混合注意力/Mamba模型还受完整状态检查点和块对齐限制。参考块大小1536，不能因为界面显示同一对话就认为任意长度历史都可立即复用。前缀匹配单位或共享Mamba检查点必须与当前vLLM、模型、MTP、PD及缓存连接器逐项核对，不能仅为提高百分比开启未知组合。

vLLM日志的窗口统计、客户端按请求统计、按词元加权统计和CPU池命中并不是同一口径。比较时至少记录查询词元、GPU命中词元、CPU实际取回词元、新输入与运行时间；不要把GPU前缀命中写成CPU缓存收益，也不要和其他服务商不同计费口径直接比较。

## 是否保留CPU共享缓存

经验中1P1D的开关差距可能很小：相同P已能保留大多数可复用前缀，CPU实际读回很少。多P、长历史频繁挤出GPU、用户并发或跨引擎路由时，CPU池才更可能提供额外复用。CPU查找和H2D搬运也有成本，因此“开了必快”以及“关了必快”都不成立。

参考方案同时保留开关选择。容量由本次用户给出，并检查系统余量；只绑定P，不能扩大D活动请求的GPU KV容量，也不能保证D永不重算。若池长期几乎没有读回、系统内存紧张或首字长尾变差，应在相同输入分布和并发下对照，而非只看命中率。缓存是易失性能层，停止/重启不保留热状态。

## 下一次应该怎样测

先授权隔离外部请求，避免全局引擎计数混入业务；读取网关已有数据必须获得授权，原始请求和数据库始终留在私有位置。按输入长度、未命中输入、输出长度、图片、到达间隔与并发分布生成脱敏负载，再测小、中、大和接近上限的上下文。

分别报告端到端首字、网关排队、上游连接/首字、P排队与处理、D生成速度、GPU与CPU缓存实际读回、抢占、失败、GPU/内存峰值。延迟给平均、中位、P95、P99、最小和最大值，吞吐区分累计服务处理率与整段墙钟吞吐。短样本不能给出稳定P99或生产性能承诺；版本、图缓存、MTP接受率和输入复用必须一致。

固定nightly与#6204在本仓库代表软件修正来源；没有附带该版本新的生产提速百分比。更大的KV容量属于容量变化，不能替代prefill、decode和长尾的实际对照。
