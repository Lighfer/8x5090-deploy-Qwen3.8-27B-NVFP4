# 公开规范与AI使用

## 什么可以进入仓库

允许通用源码、模板、补丁、固定公共软件/模型来源、许可证、合成测试以及不含现场信息的验证说明。不允许IP、主机安装路径、端口分配、网卡、GPU序号、资源名称/编号、账号凭据、运行快照、业务请求、数据库、日志、构建目录或镜像备份。即使被Git忽略，也不能放在仓库内。

上游要求的容器内部接口和路径是明确例外，例如Docker socket、`/var/lib/gpustack`、`/proc/meminfo`、`/sys/fs/cgroup`、内部回环健康接口，以及构建容器的`/build`。它们是协议约定，不是主机安装目录。真实主机身份只在用户提供的仓库外环境文件中填写。

## 每次开始先问

AI先读AGENTS.md、README及相关源码，再询问本次是仅维护源码还是操作目标环境。涉及目标环境时，必须由用户提供环境、现有服务、资源预算及允许范围；没有输入就不能猜测或沿用别人的参数。先调研、分析、设计与验证计划，再开发或部署，需决策时询问用户。

推荐提示词已放在[README](../README.md#让ai协助使用)。现场连接方式、密码和批准记录通过用户自己的私有渠道提供，不能加入环境示例或公开聊天转录。

## 源码自查

```bash
# Python3.11及以上；-B避免把字节码写入源码。
python3 -B -m unittest discover -s tests -v
python3 -B tools/verify-source.py --work "$VERIFY_DIR"
python3 -B tools/audit-public.py
python3 -B tools/verify-integrity.py
```

合成测试在系统临时目录建立两个不同环境、非连续卡号和不同端口，覆盖缺输入、编号适配、不覆盖手工变化、启停、六卡保护及回滚。源码重放只写外部目录。实际Compose、systemd、Nginx及GPU模型验收还需在目标Linux环境按部署文档执行。

修改公共内容经过审查后，运行`tools/refresh-manifest.py --execute`重建MANIFEST.json和SHA256SUMS，然后重新核对。不能先无条件重建清单来掩盖未知修改。

## Git与归档

```bash
# 实际私有标记保存在仓库外，不能写进扫描规则源码或提交。
python3 -B tools/audit-public.py --with-git --deny-file "$PRIVATE_MARKERS"
python3 -B tools/package-repository.py --output "$PUBLIC_ARCHIVE"
```

扫描包括工作树、全部Git对象和元数据，含不再被分支引用的对象；只删除当前文件不足以清除旧历史。公开转换应从已经审查的源码创建全新Git历史，原私有仓库移到仓库外备份，不复制旧`.git`。

打包器只接受内容已提交、完整性通过、全部Git对象审查通过的独立仓库，输出必须在仓库外，归档含公开Git和源码。发布前在独立目录解包，再做完整性、Git fsck、历史扫描与测试。打包器不会删除旧历史来替用户掩盖问题。

模式扫描不能证明所有自然语言都绝无隐私，必须逐目录人工读回，并与仓库外私有标记比对。测试成功只代表已说明的范围，不能声称完成另一台机器的GPU验收或新的性能压测。
