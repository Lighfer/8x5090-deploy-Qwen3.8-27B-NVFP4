# 升级、恢复与排障

## 升级顺序

每次开始先询问本次环境和允许操作范围，读取真实运行状态；仓库不保存“某台生产机当前状态”。先比较新版官方提交与本地补丁，确定哪些已上游修复、哪些需要重新实现。未知源码SHA时停止应用，不得放宽校验让构建勉强通过。

新GPUStack需重新核对模型导入、角色、缓存提供方和Worker挂载；新vLLM需核对参数名、默认值、模型runner、MTP与PD传输协议；换框架要确认真实连接器和指标接口，不能只换镜像；换模型要重新验证架构、词元模板、KV布局、Mamba状态、MTP、解析器和视觉内存。

在仓库外创建新构建目录、新镜像标签和新的私有配置备份。先做源码、无GPU和回环协议检查，再在用户授权GPU上验证小中大输入、默认xhigh、图片、工具、MTP实际接受、PD实际传输及CPU缓存独立读回。最后按业务分布验收并发、排队、内存峰值、所有方案方向和失败回滚，更新公共软件锁及文档，不把现场结果或身份写回仓库。

## 典型故障

| 现象 | 优先检查 | 处理边界 |
| --- | --- | --- |
| NVIDIA驱动正常，Docker无nvidia运行时 | `docker info`运行时清单、NVIDIA Container Toolkit与LXC设备映射 | 安装/重配Docker前确认维护窗口；不擅自重启全机Docker |
| Worker上报宿主而非LXC内存 | LXCFS meminfo、根cgroup只读挂载和实际加载模块 | 不写固定容量，不用Worker容器用量代替LXC整体 |
| P反复重启，显存仍被占用 | GPUStack重建事件、Docker日志与退出码、内核/cgroup OOM、CUDA IPC持有者 | 先保留证据；按整组停止释放P/D和关联池，不反复单拉P |
| HTTP健康却首字卡住 | 全部成员、NIXL握手线程、P/D实际参数、连接器就绪和传输错误 | 不能只看HTTP200，不能用HTTP探测握手二进制端口 |
| 启动退出码2 | JSON参数原始字符串、重复参数、框架参数版本 | 参数格式错误不是OOM；保留标准JSON，不二次转义 |
| 显存调优警告 | 是否仅跳过候选、是否持续进展、后续是否未捕获OOM | 不能仅凭一条警告强杀，也不能长期健康失败仍开放入口 |
| 多图或D启动失败 | 完整视觉启动分析、分块设置、D批量预算 | 保留分析，不靠跳过预热、关闭检查或盲目增大显存比例绕过 |
| 停止时容器突然不存在 | 再次列表和单个inspect确认GPUStack是否已正常删除 | 只忽略明确消失；Docker不可用、权限或对象仍在需报错 |
| 首字慢但P并发未满 | 网关时间分解、未命中新输入、P服务时间、CPU查询/传输、同步调用 | running/usage低不能直接排除服务串行或同步等待 |

NVFP4写缓存同步问题的修正见[补丁与构建](04-补丁与构建.md)。FlashInfer启动JIT属于正常可再生编译，加载数分钟不能仅凭一次超时视为崩溃。OOM调查应同时看内核、cgroup memory.events、容器退出状态及平台事件；没有日志不等于没有发生，也不能虚构首次退出原因。

## 日志与私有数据

运行日志、数据库、请求内容、事务备份与systemd日志均保存在用户自己的部署/证据位置，不进入公共仓库。对外分享问题时，只提供最小脱敏片段和公开软件版本。原始记录应设置容量、轮转和保留期限；自动重启次数、首次退出时间和此前日志应在清理前保留。

## 回滚和恢复

运行私有目录的`switch-pd.sh status`确认事务。切换失败会按快照恢复配置、缓存所属关系和原启停状态；恢复失败入口继续503，执行`recover`重试。SIGKILL不能由原进程捕获，独立systemd退出处理及开机恢复服务接管未完成事务。

恢复已停服务用`start`，不是再次运行生成器覆盖安装。生成器的`--configure-only`用于首次网页注册后的编号适配，遇到受管文件手工变化拒绝覆盖。升级时先备份私有文件，审查差异后明确迁移，不能删掉校验绕过保护。

源码重建可恢复软件与模型输入，不恢复账号、数据库、历史事务或热缓存。用户需在仓库外管理平台数据卷、私有配置、凭据及已验收镜像的备份。公开归档只带源码与全新公开Git历史，不能夹带生产备份。
